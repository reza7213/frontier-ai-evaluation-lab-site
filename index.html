What improves the reliability of a small language model on financial-research tasks?

See the measured results ↓

By Reza Madad · AI product leader

EXECUTIVE SUMMARY

The question.

How do model adaptation and explicit verification address incorrect calculations, unsupported answers and misleading citations?

What I built.

A reproducible study of Qwen3-0.6B, LoRA/QLoRA variants and a separate verified-tool workflow, with synthetic research tasks, source-linked traces, GPU profiling and 57 regression tests.

Three findings.

LoRA increased exact validation reference matches from 0/60 to 44/60, but arithmetic errors remained. An observed margin error passed an ID-only citation check, showing why valid references do not establish correctness. The experimental grader rejected both correct diagnostic examples, making it unsuitable as an automated release gate.

Proposed direction.

Use verified calculations and visible source evidence for numeric answers. Keep automated judging advisory until independently calibrated. Broader model comparisons, real-report evaluation and measured operating costs are planned extensions.

Initial synthetic-data study; no production readiness claimed.

THE FAILURE THAT MOTIVATED VERIFICATION

A valid citation can still support a wrong answer.

The baseline confused operating income with operating margin. The source IDs existed, so the initial citation checker passed the answer. This case shows why numeric answers need checks of the calculation and the supporting evidence.

OBSERVED BASELINE FAILURE

“Compare their FY2025 operating margins.”

“The operating margins … were $35 million … and $14 million.”

The model reported income in dollars as a margin. An ID-only citation check missed the error.

SOURCE-BASED CALCULATION
35 / 150 × 100 = 23.33%

THE PROBLEM

The broader problem: choosing models with evidence.

Teams choosing an LLM need to know how often a research task succeeds, whether its claims are supported, how the system handles failure, and what each successful task costs. Those outcomes depend on the model, prompts, retrieval, tools and infrastructure.

The first study establishes an evaluation workflow: record a baseline, inspect failures, test adapter or tool interventions, and rerun fixed checks. It provides an initial implementation and evidence base for broader comparisons.

Broader evaluation goals and what the first study actually measured

Accuracy & groundingIs the answer correct and supported by the supplied sources?Exact reference matching, AI-assisted inspection of test nonmatches, citation-ID coverage and typed calculation checks. Reliability & safetyDoes the system handle missing facts, tool failures and adversarial inputs?Known synthetic abstention, injection, restricted-data, timeout/retry and corrupted-calculation cases, plus regression checks. General real-world reliability remains untested.
Latency & resourcesHow long does generation take, and what resources does it consume?Defined T4 generation workloads, aggregate throughput, training-memory measurements and profiler traces. Production traffic and a multi-provider serving comparison were not tested.
Cost & valueWhat is the full cost per verified successful task?Planned measurement: compute, retries and human review per verified success. Only the framework and illustrative value assumptions were prepared; actual operating cost was not measured.

Completed starting point: one small open-weight model family, adapter comparisons and a separate deterministic tool workflow. Planned extensions: multiple distinct frontier models, measured cost comparisons, real public reports and independent human validation.

FROM FAILURE ANALYSIS TO INTERVENTIONS

Measured changes and unresolved errors.

Improvements are evaluated against a specific failure and metric. A higher formatting score is not automatically better factual accuracy.

01

More consistent reference formatting and citations

On the matched validation set, LoRA produced 44/60 exact normalized reference matches versus 0/60 for the base model, and required citation-ID coverage rose from 0/60 to 60/60. Exact matching is conservative: the base model sometimes gave correct facts in a different format or without citations.

Intervention: LoRA
Matched prompts & decoding
Metric: reference & ID checks
02

A verified path for the observed arithmetic failure

The original margin answer reported income in dollars. The tool workflow calculates Aurora’s 23.33% and Nova’s 10.00% margins, binds the operands to source IDs, and checks the 13.33 percentage-point gap. Its 100/100 held-out synthetic fixture result belongs to this bounded workflow, not the language model.

Decimal + Fraction checks

03

Failure evidence that changes the next experiment

Fourteen LoRA test failures remain after AI review within the fixed tolerance. The small grader rejected correct answers, and the Qwen reward smoke made no updates. Those outcomes keep human review, real-report validation and broader model/cost comparisons in the next phase.

03 / HOW THE LAB WORKS

How the first study was run.

The model track compares configurations within Qwen3-0.6B under matched generation settings. A separate deterministic tool track tests source-bound retrieval, calculation and verification. Their tasks and scores remain distinct; this is not a comparison of multiple frontier LLMs.

A

Adapt and evaluate the model

Qwen3-0.6B with LoRA and QLoRA adapters. Grouped synthetic splits: 360 training, 60 validation and 60 test examples. Thinking disabled; source documents injected into each model prompt. LoRA was selected on validation before the reserved test run.

B

Retrieve, calculate and verify

A controlled Python workflow filters company and period, retrieves with BM25, calculates with Decimal, and independently checks typed claims with Fraction arithmetic. Stable document IDs bind the operands to their sources. MCP stdio tools add an explicit integration boundary.

Keep failure evidence

100/100 bounded synthetic workflow fixtures

50 financial cases and 50 behavior fixtures across ten families passed in the separate deterministic workflow. These use familiar templates with new synthetic entities or values. This tests the bounded workflow; it is not a language-model accuracy score or evidence of general research reliability.

04 / PRODUCT JUDGMENT

Proposed next step.

A supervised pilot that makes sources, operands and uncertainty visible.

The study provides a transparent verification path for a demonstrated failure. The next investment is testing that mechanism on real public reports and real analyst workflows.

Open validation gates

  • Second independent reviewer’s actual labels and a larger blind calibration set.
  • Real-report evaluation, including conflicting periods, restatements and unsupported questions.
  • Production privacy controls, service targets and measured cost per verified success.

The project does not establish production readiness, general semantic citation precision or a successful language-model RL outcome.
